# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added

- Firmware update entity for SDCP V3 printers: new printer firmware now shows up in **Settings → Updates** with Elegoo's changelog as release notes, instead of only as the diagnostic Firmware Update Available binary sensor (which stays). Read-only - SDCP has no install command, so the update is still installed from the printer's screen.
- Print file and print tray selects with Refresh File List and Print Selected File buttons for the Centauri Carbon 2: the files in the printer's local storage (method 1044), a tray to print from, and a button to start. Choosing never starts a print; the button does.
- Canvas (AMS) support for the Centauri Carbon (CC1): per-slot filament sensors, active tray, and filament colors, matching the existing CC2 support. Canvas presence is auto-detected during setup and stored per printer.
- Per-slot filament usage sensors for the CC1 via the gcode capture proxy. The proxy URL is now configured in the WebSocket printer options, and works with or without a Canvas installed.
- New FDM print states reported verbatim from the printer — auto leveling, resonance testing, preheating/homing/leveling completed, auto feeding, and filament unload states — with an explicit `unrecognized` fallback so unknown codes can no longer freeze the status sensor.
- New `upload_gcode` service for the Centauri Carbon 2: pick a G-code file in the Developer Tools UI, have it uploaded to the printer's storage over the LAN, and optionally start it right away.
- New `start_print` service for the Centauri Carbon 2: start a G-code file already in the printer's storage from the Developer Tools UI or an automation, optionally on a chosen Canvas tray, with auto bed leveling on by default as in the slicer; the response reports whether the printer accepted the job.
- New `update_ip` service: change a printer's IP address from the Developer Tools UI or an automation (e.g. an external IP-detection script) without deleting and re-adding the integration; the config entry reloads with the new address and the service reports whether the printer is reachable at it.
- New **Proxy Host** option for the Centauri Carbon 2: point the whole integration at a forward proxy (e.g. [elegoo-printer-proxy](https://github.com/lantern-eight/elegoo-printer-proxy)) instead of only borrowing its parsed G-code data. MQTT control, G-code uploads and the camera all then go to the proxy on the printer's usual ports, which is what you want when Home Assistant can only reach the printer through the proxy (different network or VLAN) or when you would rather the camera came from the proxy too. It does not reduce the number of connections the printer sees — the proxy is a plain pass-through, one printer connection per client connection — so it is not a fix for the printer's connection limit. Discovery does not answer on a proxy, so it is skipped and the serial is learned from the printer's own MQTT status messages, with a prompt if the printer pushes nothing. Leave the field blank to connect directly, as before.
- Filled in 21 previously-untranslated UI strings (proxy host, serial entry,
     MQTT options, file-select entities) across all 17 non-English locales.
     Machine-translated and structurally validated; not yet reviewed by native
     speakers — corrections welcome (PR to the `translations/` directory).
- Translation parity tests: every code-referenced error key must exist in
     `en.json`, and all locale files must carry the same key set as `en.json`.
- New **"Printer is often switched off"** option in every printer's options (WebSocket, MQTT and Centauri Carbon 2 alike), for a printer that is normally powered down — off at the wall, or switched by a smart plug between prints. Ticking it lets setup finish even when the printer can't be reached: instead of **"Failed setup, will retry"**, the entities sit at **"Unavailable"** and come back on their own within **a minute or so** (a couple of polls — the poll that notices the printer is back spends itself reconnecting) once the printer is powered on, with no restart and no reload. The box can be ticked **while the printer is switched off**, so a printer you power on once a month is no longer locked out of its own settings, and saving the options reloads the entry immediately. Left unticked, which is the default, behaviour is exactly as before. Accepted trade-off: a wrong IP address or dead hardware then looks identical to a switched-off printer, so if it never comes back, check the single `without a connection` line the integration logs once at setup. Reported by @oblivioncth in #171.

### Changed

- FDM print status codes now map 1:1 from the printer's own status table instead of being approximated through resin states; mid-print milestones no longer surface as misleading states like "leveling".
- Config entries migrate automatically (v4 → v5) to record the per-printer Canvas flag; no action is needed.

### Fixed

- Begin Time no longer shows "1 January 1970" when the printer reports a 1970 start time (seen on a Centauri Carbon after a restart). It is now worked out from the elapsed print time, and a 1970 End Time reads as unknown.
- A failed firmware check (e.g. Elegoo's server unreachable) no longer resets Firmware Update Available to "no update" until the next check 12 hours later; the last known result is kept.
- WebSocket discovery now recognizes hostnames by their resolved IPv4 address, and options updates validate the newly submitted address.
- CC1 print status no longer sticks on a stale state for the remainder of a job when the printer holds an unmapped milestone code.
- The Canvas auto-detection step in setup is bounded by a timeout, so a device that accepts connections but never answers can no longer hang the config flow.
- `bed_leveling: false` on the CC2 now sends `printer_check: false` instead of leaving the key out. Measured on firmware 02.01.00.00: the printer remembers the last value it was given, so an omitted key means "carry on as before" rather than "off" - a job that omits it after one that sent true levels again, even with the bed temperature unchanged. An explicit false skips leveling (first layer at 180 s instead of 398 s). ElegooSlicer sends false the same way when its own bed-leveling box is unchecked.
- The "invalid IP" error during manual IP entry now shows a proper message
     instead of a raw translation key (the key was missing from the English base
     and every locale).
- **Applies to all users, with or without the new option:** a Centauri Carbon 2 printer that drops off mid-session now goes **"Unavailable"** instead of carrying on with cached values — 0 °C, "idle", fans off — served as though they were live readings. The MQTT-backed transports — the Centauri Carbon 2 and a plain MQTT printer — answer a status request from cache without complaining, so a poll of a printer that has gone away used to "succeed" and every entity rendered fabricated defaults as fact. A default is not a measurement, and acting on one (a bed that will never heat, a print that looks finished because the state reads idle) was worse than an honest greyed-out entity. This is a bug fix, but it is a visible change for anyone whose printer connects and disconnects. **Known gap, same behaviour as before this change:** an MQTT printer whose broker *outlives* it — an external broker, or this integration's own embedded broker, which the printer dials into rather than hosts — keeps answering from that cache, because what the integration can see is the link to the broker, and that link stays up when the printer walks away. Closing it needs a printer-side heartbeat and is recorded in `docs/roadmap/offline-tolerant-setup.md`. Reported by @oblivioncth in #171.
- **Applies to all users, with or without the new option:** the **"Connection to printer … lost, attempting to reconnect"** line is now written **once**, at the moment a live connection drops, instead of on every 30-second poll — a printer that is simply switched off used to produce that line roughly **2,880 times a day**, which is the log-spam half of @oblivioncth's report in #171. The attempts that follow are still recorded, at debug level, for whoever ends up debugging it. A printer that never connected also says **"not reachable yet"** rather than "lost", because it never had a connection to lose.
- **Applies to all users too, option or not:** the **options forms for WebSocket, MQTT and Centauri Carbon 2 printers now refuse a blank IP address** instead of saving it. Those steps save without testing the connection, so clearing the address field and pressing Submit used to persist an empty address silently — an entry that can never connect, and one that fails silently if the offline option is ticked too. The form reopens with the *enter a valid IP* error and nothing is saved — in every language, because the message was also added to the `options.error` translation namespace, which Home Assistant consults for options flows instead of falling back to the setup-flow one.
- Saving a printer's options **while the printer is switched off** no longer writes `ERROR` lines to the log, and no longer dumps a traceback for the failures that produce one. With the option ticked, a printer that cannot answer the connection test is the expected case and the save is meant to go ahead, so that test failure is recorded at debug level instead; leave the box unticked and a failed test is still an error, because then it genuinely is one.
- Unloading a printer that came up **offline** no longer tears down the shared G-code proxy server out from under another printer that is using it. The offline entry never started the proxy, so it holds no reference of its own; releasing one anyway decremented a live entry's count and could stop the server under a printer that was still capturing G-code.
- **Applies to every printer that was ever added with the option ticked:** a reconnect attempt that fails on the handshake no longer brings the printer back as if it had answered. A switched-off MQTT printer answers the broker probe (the broker is ours) and then refuses the handshake, and that timeout used to escape the reconnect path into Home Assistant's error handling — which printed `Unexpected error fetching <printer> data` with a full traceback every 30 seconds, and left the client half-connected. The *next* poll then believed the printer was back, published its empty cache as a live reading (0 °C, "idle", fans off) and stopped trying to reconnect at all, so a printer that was never powered on sat on the dashboard as healthy. It now stays **Unavailable** until the printer genuinely answers, on every poll, with at most one **INFO** line when the connection drops and debug lines after it — never a traceback. Found in the #171 review.
- Two printer entries that hold the **same IP address** — a duplicate left behind for a printer that was replaced, or a DHCP lease that moved between machines — no longer delete each other from the shared proxy registry. The registry is keyed by address, so unloading one entry used to deregister the other printer, and a printer with no registry entry stops being routed to and broadcast at by the proxy even though its own entry is live. The registration is now matched by mainboard id before anything is removed.
- Setting up an entry that tolerates a switched-off printer no longer ends in a hard **Setup Error** if the tidy-up after the failed reachability test itself fails. That exit now tears the connection down the same way the other two tolerated exits do — errors there are expected when nothing answered, and used to escape setup as an unhandled exception.

### Breaking Changes

- The unique ID format for entities has changed to include the machine ID. This may cause Home Assistant to create new entities. The integration will attempt to migrate existing entities to the new format, but this may not be successful in all cases. If you experience issues, you may need to remove and re-add the integration.
